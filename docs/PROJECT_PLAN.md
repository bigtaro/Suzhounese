# 苏州方言语音识别项目规划

> 版本：v0.1  
> 日期：2026-11-20  
> 默认假设：1–2 人小团队，先做离线汉字转写 MVP，使用单张 24 GB 左右 GPU 迭代。

## 1. 项目摘要

目标是构建一个能够识别苏州方言的语音识别系统。项目不直接从零训练，而是基于现有语音模型做方言适配，并用“少量精标数据 + 伪标注 + 语言模型/热词”逐步提升效果。

首版聚焦苏州城区口音、较清晰的朗读和自然对话，输出汉字转写。拼音/IPA、实时识别、更多县市口音作为后续阶段扩展。

## 2. 项目目标

### 2.1 阶段目标

| 阶段 | 目标 | 核心交付 |
|---|---|---|
| P0 基线 | 建立可复现的评测和基线 | 测试集、评测脚本、zero-shot 报告 |
| P1 原型 | 用 10–20 小时精标数据跑通 LoRA 微调 | 可用的离线转写模型、首版错误分析 |
| P2 可用 MVP | 30–50 小时数据，加入回放、伪标注和热词 | CER 明显下降的模型、推理脚本 |
| P3 扩展 | 80–100 小时以上数据，覆盖更多说话人和场景 | 更稳健的模型、部署包、模型卡 |

### 2.2 非目标

- 首版不追求覆盖全部吴语或全部苏州县市口音。
- 首版不做语音翻译；如果标签写普通话意译，模型学到的会是翻译而不是转写。
- 首版不做苏州话语音合成。
- 首版不承诺电话客服级远场、强噪声、多人重叠场景。

## 3. 默认假设与待确认决策

### 3.1 默认假设

- 目标口音：苏州城区苏州话为主，后续再扩吴江、昆山、常熟、张家港、太仓等口音。
- 目标人群：中老年为主，同时包含年轻说话人，避免只覆盖单一年龄层。
- 语音类型：朗读和自然对话都做，但分别报告结果。
- 语言现象：允许普通话/苏州话混说，混说样本单独标记。
- 输出格式：汉字转写为主；如有拼音标注，额外报告 PER。
- 部署形态：先离线批处理，实时流式放到 P3。

### 3.2 需要确认的决策

| 编号 | 决策 | 默认选择 | 影响 |
|---|---|---|---|
| D1 | 目标口音范围 | 苏州城区 | 决定数据采集和测试集构成 |
| D2 | 输出格式 | 汉字转写 | 决定标注规范、词表和评测方式 |
| D3 | 是否实时 | 首版离线 | 决定模型选择和推理架构 |
| D4 | 数据来源 | 自采且有授权 | 决定项目周期和合规风险 |
| D5 | 部署硬件 | 单机 GPU/CPU | 决定量化和模型大小 |
| D6 | 是否保留拼音 | 可选 | 决定是否建立发音词典和 PER 评测 |

## 4. 成功标准

### 4.1 过程指标

- 测试集至少 2 小时，覆盖不少于 30 位说话人。
- 训练、验证、测试严格按说话人和录音场次隔离。
- 至少 10% 的训练数据做双人标注，字级一致率目标不低于 90%。
- 每次实验都有固定随机种子、配置文件和评测报告。
- 每个模型版本都能复现数据切分和推理命令。

### 4.2 效果指标

以下为草案，P0 基线完成后冻结具体数值：

- P1：相对 zero-shot 基线，测试集 CER 相对下降至少 15%。
- P2：相对基线 CER 相对下降至少 30%；朗读语音 CER 目标不高于 20%，自然对话不高于 35%。
- P3：朗读语音 CER 目标不高于 15%，自然对话不高于 30%。
- 幻觉率低于 2%，即音频无对应内容却输出流畅文本的比例。
- 离线推理 RTF 小于 1.0；实时版本首字延迟满足产品需求。

注意：苏州话没有完全统一的书写规范，CER 必须配合统一转写规范和人工可懂度评估，不能只看单一数字。

## 5. 技术路线

### 5.1 主路线

1. 用 Whisper large-v3 和 Paraformer 做 zero-shot 基线，确认模型对苏州话的真实表现。
2. 用 Whisper large-v3 做 LoRA 微调，优先适配声学编码器。
3. 混入 10%–20% 普通话数据，降低灾难性遗忘。
4. 用伪标注扩展无标注音频，人工抽检后迭代。
5. 加入字符级 n-gram 语言模型、领域热词和上下文偏置。
6. 数据超过 50 小时后，再评估全参微调、Whisper turbo 或其他模型。

### 5.2 备选路线

- FunASR/Paraformer：适合中文、实时和低成本部署，但需要先验证方言 zero-shot 能力。
- XLS-R/wav2vec2 + CTC：适合低资源音素级建模，需要发音词典和语言模型。
- SenseVoice/Qwen-Audio 类模型：适合探索富文本输出，但不应假设其天然支持吴语。

### 5.3 首版训练配置建议

| 项目 | 建议 |
|---|---|
| 采样率 | 16 kHz，单声道 |
| 音频长度 | 5–30 秒，按长度组 batch |
| 初始化 | `openai/whisper-large-v3` |
| 微调方式 | LoRA，注意力 q/k/v/o + FFN |
| LoRA rank | 16–32 |
| 学习率 | LoRA 约 1e-4；全参微调编码器约 1e-5 |
| 精度 | bf16/fp16 + gradient checkpointing |
| 训练轮数 | 10–20，按验证集 CER 早停 |
| 数据混合 | 90% 苏州话 + 10% 普通话起步 |
| 增强 | 轻度速度扰动、增益、噪声、SpecAugment |

## 6. 数据计划

### 6.1 数据量

| 阶段 | 精标训练集 | 测试集 | 说明 |
|---|---:|---:|---|
| P0 | 0–5 小时 | 2 小时 | 先建立基线 |
| P1 | 10–20 小时 | 2–3 小时 | 跑通 LoRA |
| P2 | 30–50 小时 | 3–5 小时 | 加入伪标注和更多说话人 |
| P3 | 80–100 小时+ | 5 小时+ | 覆盖更多口音和场景 |

有效时长按 VAD 后的语音时长计算，不按原始录音文件时长计算。

### 6.2 数据来源

- 有知情同意书的自采访谈、朗读和日常对话。
- 社区、学校、文化机构合作采集的授权录音。
- 广播、电视、播客等有明确使用授权的音频。
- 可公开使用且有许可证的方言语料。

不建议直接抓取版权不明的音频。涉及个人信息时，保存同意记录，音频和文本中使用匿名说话人编号。

### 6.3 数据切分

- 训练/验证/测试按 80/10/10 左右切分。
- 必须按 `speaker_id` 和 `session_id` 隔离，禁止同一说话人或同一场录音跨集合。
- 测试集按年龄、地区、性别、朗读/对话、噪声条件分层。
- 额外保留一个 hard test：老年人、自然对话、远场、普苏混说、专有名词。

## 7. 标注规范

### 7.1 标注原则

- 转写必须忠实于实际发音，不把苏州话自动“翻译”成普通话。
- 先确定汉字转写规范，再开始大规模标注。
- 语气词、停顿、重复、口误是否保留，要在规范中写明。
- 数字、英文、普通话混说、专有名词要有统一写法。
- 同一发音对应多个汉字时，规定“本字优先、俗字次之、同音字兜底”的优先级。
- 如果做拼音标注，使用苏州话拼音、吴语拼音或 IPA，不能直接用普通话拼音。

### 7.2 质量控制

- 先标注 30–60 分钟作为试标，开校准会后再批量生产。
- 10% 样本双人标注，争议由第三人裁决。
- 每周抽检 5%–10% 已标注数据，统计字级一致率和错误类型。
- 建立易错词表：地名、人名、亲属称谓、语气词、连读变调、入声字。
- 伪标签必须经过置信度筛选和人工抽检，不能直接全量当金标准。

### 7.3 推荐工具

- 切分和试听：Audacity、Praat。
- 人工转写和对齐：ELAN、Label Studio 或自建标注页。
- 批量预标注：先用 Whisper/Paraformer 生成初稿，再由母语者校对。
- 强制对齐：数据量足够后，用自定义发音词典的 MFA 做音节级对齐。

## 8. 实验计划

| 实验 | 数据 | 模型/改动 | 目的 |
|---|---|---|---|
| E0 | 0 小时 | Whisper large-v3 zero-shot | 建立基线，识别主要失败模式 |
| E0b | 0 小时 | Paraformer zero-shot | 对比中文模型路线 |
| E1 | 10 小时 | Whisper LoRA | 验证方言适配是否有效 |
| E2 | 20–30 小时 | Whisper LoRA | 观察数据量收益 |
| E3 | E2 + 10% 普通话 | 数据回放 | 检查普通话遗忘和混说表现 |
| E4 | E2 + 伪标注 | 自训练 | 验证无标注数据价值 |
| E5 | 50 小时+ | 全参微调或更大 rank | 判断是否值得增加算力 |
| E6 | 最佳模型 + LM/热词 | 语言模型、领域词表 | 降低专有名词和常见词错误 |
| E7 | 最佳数据 | CTC/Paraformer 对比 | 评估实时和部署路线 |

每次只改变一个变量，记录数据版本、模型版本、超参数、随机种子和评测结果。

## 11. 评测方案

### 11.1 指标

- CER：汉字级错误率，主指标。
- PER：音素/音节错误率，有拼音标注时使用。
- 幻觉率：无语音或低信噪比音频上产生无关文本的比例。
- RTF：推理耗时与音频时长的比值。
- 人工可懂度：母语者按 1–5 分评价转写是否保留原意。

### 11.2 报告维度

- 全部测试集。
- 朗读 vs 自然对话。
- 老年 vs 年轻。
- 城区 vs 郊区/其他口音。
- 安静 vs 噪声/远场。
- 纯苏州话 vs 普苏混说。
- 常见词 vs 人名地名等专有名词。

### 11.3 错误分类

- 声母错误。
- 韵母错误。
- 声调和连读变调错误。
- 词汇/本字选择错误。
- 普苏混说切换错误。
- 语气词、停顿、重复处理错误。
- 人名、地名、专有名词错误。
- Whisper 幻觉或输出普通话意译。

## 12. 部署方案

- 首版提供命令行批量转写和简单 HTTP API。
- 推理前加 VAD 和音频重采样，长音频按静音切段。
- 低置信度片段提示人工复核，不直接输出高置信度假结果。
- 用 int8 量化、ONNX/TensorRT 或 CTranslate2 评估 CPU/GPU 性能。
- 实时版本优先考虑流式 Paraformer 或 Whisper turbo，并单独测试首字延迟。
- 保留普通话 fallback 和领域热词机制。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 标注数据不足 | 模型只能记住少数说话人 | 数据飞轮、伪标注、社区合作、先做窄领域 |
| 转写规范不统一 | CER 不可比、模型标签冲突 | 先试标、双标、争议裁决、版本化规范 |
| 说话人泄漏 | 测试结果虚高 | 按 speaker/session 切分，脚本自动检查 |
| 过拟合 | 训练集好、真实场景差 | 早停、数据增强、回放、多场景测试集 |
| 灾难性遗忘 | 普通话能力下降 | 混入普通话数据、LoRA、分层学习率 |
| Whisper 幻觉 | 输出流畅但错误的内容 | VAD、no-speech 阈值、置信度、人工复核 |
| 算力不足 | 训练周期长 | LoRA、混合精度、梯度累积、云 GPU |
| 版权和隐私 | 数据不可用或合规风险 | 知情同意、授权书、匿名化、本地处理 |
